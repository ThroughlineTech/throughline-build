## CLI verbs (the `build` binary)

All verbs are dispatched from [src/ThroughlineBuild.Cli/Program.cs](../../src/ThroughlineBuild.Cli/Program.cs) (single top-level entry point, ~2298 lines). Verb dispatch is still a chain of `if (verb == ...)` blocks rather than a registry. Help is no longer the single `CliUsage.UsageText` string: a tiered help system lives in `src/ThroughlineBuild.Cli/Help/`. `HelpRegistryFactory.Build` ([HelpRegistryFactory.cs:24](../../src/ThroughlineBuild.Cli/Help/HelpRegistryFactory.cs#L24)) declares one `HelpModel` per command (19 entries, grouped Pipeline / Work items / Configure); `Tier0Renderer.Render` produces the grouped top-level menu for `build`, `build -h|--help`, and bare `build help` ([Program.cs:33-45](../../src/ThroughlineBuild.Cli/Program.cs#L33-L45)); `Tier1Renderer.Render` produces per-command help when `-h`/`--help` appears anywhere after a verb ([Program.cs:152-170](../../src/ThroughlineBuild.Cli/Program.cs#L152-L170)); and `HelpTopicRegistry.Build` declares four reference topics - `config`, `digest`, `exit-codes`, `summary` - served by `build help <topic>` ([HelpTopicRegistry.cs:30-35](../../src/ThroughlineBuild.Cli/Help/Topics/HelpTopicRegistry.cs#L30-L35), dispatch [Program.cs:39-56](../../src/ThroughlineBuild.Cli/Program.cs#L39-L56)). `build -V|--version` prints `BuildVersion.Current` ([Program.cs:27-31](../../src/ThroughlineBuild.Cli/Program.cs#L27-L31)).

Several pre-passes run before verb dispatch: ten bare bool flags - `--debug`, `--quiet`, `--summary-json`, `--error-location`, `--no-auto-resolve`, `--no-auto-merge`, `--no-push`, `--continue-past-failure`, `--from-brief`, `--skip-baseline` - are stripped first ([Program.cs:61-100](../../src/ThroughlineBuild.Cli/Program.cs#L61-L100)); then `CliArgParser.ExtractAgentFlags` pulls the `--agent` / `--agent-plan` / `--agent-implement` / `--agent-review` pairs ([CliArgParser.cs:26](../../src/ThroughlineBuild.Cli/CliArgParser.cs#L26)); for `chain` only, `ExtractChainTraversalFlags` pulls `--dry-run` / `--max-depth` and `CliArgParser.ExtractBatchImplementFlag` pulls `--batch-implement` ([Program.cs:110-135](../../src/ThroughlineBuild.Cli/Program.cs#L110-L135)); then ticket IDs for phase verbs are extracted via `CliArgParser.ExtractTicketIds` ([CliArgParser.cs:229](../../src/ThroughlineBuild.Cli/CliArgParser.cs#L229)).

Twenty-one verbs are reachable (up from 17 at the last refresh): `init`, `setup`, `settarget`, `user-guide`, `op-doc` (subverbs `spec`|`new`), `models` (subverb `refresh`), `plan`, `implement`, `review`, `ship`, `chain`, `rework`, `decompose`, `new`, `scaffold`, `sweep`, `list`, `amend`, `close`, `defer`, `reopen` - plus `help`/`--help`/`-h` and `-V`/`--version`. Any other token returns exit 2 (unknown subcommand, [Program.cs:1099-1104](../../src/ThroughlineBuild.Cli/Program.cs#L1099-L1104)). `init`, `settarget`, `user-guide`, `op-doc`, and `models refresh` all dispatch before config load (they edit or do not need `.build/config.toml`).

### `build plan <ticket-id> [ticket-id ...] [--from-brief]` - Functional
Dispatched per-ticket from the sequential multi-ticket loop ([Program.cs:1167-1182](../../src/ThroughlineBuild.Cli/Program.cs#L1167-L1182)) into the `plan` branch of `RunTicketVerbBodyAsync` ([Program.cs:1450-1498](../../src/ThroughlineBuild.Cli/Program.cs#L1450-L1498)). Investigates a `Backlog` ticket and writes the plan to the ticket description, plus risk/size labels and a `[planned_at: <sha>]` marker comment. `--from-brief` (or config `[plan] mode = "promote"`, the config default per `PlanConfig.Default`; flag wins) skips the worker and promotes the Backlog ticket to Ready using the description already on the ticket - the normal path for op-doc-scaffolded tickets.

- **Inputs:** one or more ticket ids; `--debug | --quiet`, `--summary-json`, `--error-location`, `--agent <name>`, `--from-brief`. Reads `.build/config.toml`, the Plane ticket, current main SHA, top-level cwd entries.
- **Side effects:** spawns the configured worker in the main worktree (no branch cut), writes Plane HTML description + labels + one comment, appends events to `.build/events/<stem>.jsonl`, captures worker stdio under `--debug`. Deterministic completion summary via `PhaseSummaryBuilder.BuildPlan`.
- **Exits:** 0 success, 1 phase failure, 2 missing/unknown id, 3 missing secret, 4 infra.
- **Invokes:** `PlanPhase`, `PlanBriefBuilder`, `PlaneTicketingClient`, agent via `EffectiveAgentFor("plan")`, `JsonlEventSink`.

### `build ship <ticket-id> [ticket-id ...] [--no-auto-merge --no-push --skip-baseline]` - Functional
The `ship` branch of `RunTicketVerbBodyAsync` ([Program.cs:1619-1716](../../src/ThroughlineBuild.Cli/Program.cs#L1619-L1716)). Deterministic phase, no worker subprocess. Resolves the merge target (`[work].target_branch` if set, else `[ship].base_branch` - `ShipOptions.TargetBranch` resolution at [ShipPhase.cs:251](../../src/ThroughlineBuild.Phases/ShipPhase.cs#L251)), fetches, ancestry-checks and (on clean divergence) auto-rebases, scans for conflict markers, runs `ship.regression_checks`, fast-forward-merges the feature branch, pushes the target unless pushing is disabled (`--no-push` or `[ship] push = false`, threaded as `ShipOptions.NoPush` at [Program.cs:1629](../../src/ThroughlineBuild.Cli/Program.cs#L1629)), posts `[shipped_at: <sha>]`, transitions `InReview -> Done`, decrufts the worktree.

- **Baseline awareness:** failing regression checks are compared against a per-onto-SHA baseline (`BaselineCache` in Helpers) probed by `GateControlProber`, so a check that already fails on the untouched base is not blamed on the ticket; `--skip-baseline` disables this.
- **Preflight guard:** when the target branch is non-default, ship checks the main worktree is on that branch and otherwise emits a `wrong_worktree_branch` `GateFailure` ([ShipPhase.cs:272](../../src/ThroughlineBuild.Phases/ShipPhase.cs#L272)).
- **`--debug`** makes ship verbose (streams git output and full check results to stderr via the `verbose` constructor flag, [Program.cs:1636](../../src/ThroughlineBuild.Cli/Program.cs#L1636)); phase-level progress lines print regardless.
- **Exit codes:** mapped from `ShipFailureStage` at [Program.cs:1704-1714](../../src/ThroughlineBuild.Cli/Program.cs#L1704-L1714): 0 success or post-success decruft warning; 1 rebase / conflict-marker / regression; 4 state-check / fetch / FF-merge infra.
- **Invokes:** `ShipPhase`, `ProcessGitClient`, `BaseRefResolver`, `AutomatedChecksRunner`, `ConflictMarkerScanner`, `WorktreeDecrufter`, `PhaseSummaryBuilder.BuildShip`.

### `build chain <ticket-id> [ticket-id ...] [--batch-implement [<ids>] --dry-run --max-depth <n> --no-auto-resolve --no-auto-merge --continue-past-failure --from-brief]` - Functional
The `chain` branch of `RunTicketVerbBodyAsync` ([Program.cs:1718-1727](../../src/ThroughlineBuild.Cli/Program.cs#L1718-L1727)) delegates to `RunChainVerbAsync` ([Program.cs:1762](../../src/ThroughlineBuild.Cli/Program.cs#L1762)). End-to-end orchestration, substantially rebuilt since the last refresh (op-28 chain-run defenses, op-29 tame-the-cli, op-30 deterministic gate, op-31 batch implement): each root ticket traverses its subtree **post-order with accumulated integration branches** - a parent cuts a local `chain/<slug>` branch (`ChainIntegrationBranchFromId`, [ChainPhase.cs:2966](../../src/ThroughlineBuild.Phases/ChainPhase.cs#L2966)), children ship into it (local-only, `NoPush: true` for integration ships), nested parents merge their integration branch up, and only the outermost chain lands the accumulated branch onto the configured target and pushes ([ChainPhase.cs:2776](../../src/ThroughlineBuild.Phases/ChainPhase.cs#L2776)). A reused integration branch from a prior run is refreshed against its base ref before children dispatch (TLB-546, `RefreshIntegrationBranchAsync` at [ChainPhase.cs:2232](../../src/ThroughlineBuild.Phases/ChainPhase.cs#L2232)). The implement-review loop keeps `MaxReworkRounds = 2` ([ChainPhase.cs:61](../../src/ThroughlineBuild.Phases/ChainPhase.cs#L61)). Between implement and review a deterministic `GatePhase` runs the review checks once on the warm worktree; the chain wiring also builds a `GateVacuityProver` (proves each gating check can actually fail; controlled by `[review] verify_gate_vacuity`) and a `GateControlProber` (re-runs failed checks against the untouched base ref so a broken environment is never blamed on the ticket, TLB-538) - both constructed at [Program.cs:1813-1836](../../src/ThroughlineBuild.Cli/Program.cs#L1813-L1836). Construction of the whole assembly goes through `ChainPhaseComposition.BuildChainPhase` ([ChainPhaseComposition.cs:23](../../src/ThroughlineBuild.Cli/ChainPhaseComposition.cs#L23)) so tests can verify no dependency is dropped.

- **`--dry-run`** prints the full post-order tree schedule and branch topology without executing phases (`ChainOutcome.DryRunPreview`). **`--max-depth <n>`** is root-based (default 16, `ChainPhaseOptions.MaxDepth` at [ChainPhase.cs:34](../../src/ThroughlineBuild.Phases/ChainPhase.cs#L34)); 0 is root-only. **`--batch-implement`** batches the implement phase for direct leaf children in one warm worker session - bare flag batches all eligible children, a comma list batches exactly that sibling group (validated by `ValidateBatchImplementGroupAsync`, [Program.cs:2175](../../src/ThroughlineBuild.Cli/Program.cs#L2175)); batch size caps from `[batch]` config apply, oversized groups fall back to per-ticket chain. Internal-node candidates are downgraded to per-child recursion, and `BatchCommitVerifier` checks the batch commit stack afterward.
- **Multi-ticket dispatch:** extra positional IDs build a `TicketGraph` from `blocked_by` relations and run level-synchronously through `ParallelDispatcher` with concurrency bounded by `workers.max_concurrency` ([Program.cs:1976-2060](../../src/ThroughlineBuild.Cli/Program.cs#L1976-L2060)); a residual `SequentialChainDispatcher` fallback path also remains ([Program.cs:2081-2124](../../src/ThroughlineBuild.Cli/Program.cs#L2081-L2124)). `--continue-past-failure` runs descendants of a failed ancestor anyway (default: skipped).
- **Flags:** per-phase agent overrides (`--agent-plan`/`--agent-implement`/`--agent-review`; per-phase flag beats `--agent` beats config, `EffectiveAgentFor` at [Program.cs:1149-1153](../../src/ThroughlineBuild.Cli/Program.cs#L1149-L1153)), `--no-auto-resolve`, `--no-auto-merge`, `--from-brief`, `--debug`.
- **Exit codes:** centralized in `ChainExitCodeMapper.GetExitCode` ([ChainExitCodeMapper.cs:13](../../src/ThroughlineBuild.Cli/ChainExitCodeMapper.cs#L13)): 0 Completed / RatifiedObsolete / ParentCompleted / DryRunPreview; 2 RefusedInitialState / RefusedDirtyTree / RefusedWrongBranch / ParentHasGrandchildren; 3 StoppedAtPlan / ParentStoppedEarly / Skipped; 4 StoppedAtImplement; 5 StoppedAtReview; 6 ReworkCapExceeded; 7 StoppedAtShip; 8 GateVacuous; 9 ReviewUnavailable (verifier blocked by provider quota/rate-limit/auth, TLB-527); 10 GateEnvironmentFailure (TLB-538); 11 TicketingUnavailable (transport-level Plane outage, TLB-545). The 18-value `ChainOutcome` enum is declared at [ChainOutcome.cs:3](../../src/ThroughlineBuild.Contracts/Models/ChainOutcome.cs#L3).
- **Invokes:** `ChainPhase`, `GatePhase`, `ParallelDispatcher`, `TicketGraph`, `ChainCommand`, `DefaultChainRunner`, `SequentialChainDispatcher`, `ObsoleteRatifier`, `PreComputedChecksRunner` (review reuses gate check results so each ticket builds once).

### Loose ends (CLI verbs)
- **`sweep` and `models` are missing from the help registry.** `HelpRegistryFactory.Build` declares 19 commands; `sweep` and `models` are not among them, so `build sweep --help` falls back to the tier-0 menu instead of per-command help, and neither appears in the tier-0 listing. Both ARE documented in the legacy `CliUsage.UsageText`, which production code no longer prints.
- **`CliUsage.UsageText` is Legacy.** No production code references `CliUsage` ([CliUsage.cs:3](../../src/ThroughlineBuild.Cli/CliUsage.cs#L3)) - only tests assert against it. Its text has drifted from behavior in at least one place: it claims ship `--debug` "is a no-op", but `ShipPhase` is constructed with `verbose: debugMode` and streams git/check output ([Program.cs:1636](../../src/ThroughlineBuild.Cli/Program.cs#L1636)).
- **Chain exit codes 10 and 11 are undocumented in help.** `ChainExitCodeMapper` maps `GateEnvironmentFailure -> 10` and `TicketingUnavailable -> 11`, but neither the `exit-codes` help topic (`HelpTopicContent.ExitCodes`) nor `CliUsage` lists them (both stop at 9).
- **`--n` / `--no-promote` (decompose)** and **`--all` / `--feature` (list)** remain slash-command-layer flags the CLI does not parse.
- **`build amend --ac`** still calls `UpdateDescriptionAsync` ([AmendCommand.cs:136](../../src/ThroughlineBuild.Commands/AmendCommand.cs#L136)) - the same call `--description` uses - so it replaces the whole description; if both are passed, the second write wins.
