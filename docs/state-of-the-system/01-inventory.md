## CLI verbs (the `build` binary)

All verbs are dispatched from [src/ThroughlineBuild.Cli/Program.cs](../../src/ThroughlineBuild.Cli/Program.cs) (single top-level entry point, ~2209 lines). Help text is now a real subsystem under [src/ThroughlineBuild.Cli/Help/](../../src/ThroughlineBuild.Cli/Help/): per-command `CommandHelp` records are built by [HelpRegistryFactory.cs](../../src/ThroughlineBuild.Cli/Help/HelpRegistryFactory.cs), rendered top-level (grouped Pipeline / WorkItems / Configure) by [Tier0Renderer.cs](../../src/ThroughlineBuild.Cli/Help/Tier0Renderer.cs) and per-verb (`build <verb> -h`) by [Tier1Renderer.cs](../../src/ThroughlineBuild.Cli/Help/Tier1Renderer.cs); long-form `help <topic>` pages resolve through [Help/Topics/HelpTopicRegistry.cs](../../src/ThroughlineBuild.Cli/Help/Topics/HelpTopicRegistry.cs) (four topics: `config`, `digest`, `exit-codes`, `summary`). `CliUsage.cs` is no longer referenced by `Program.cs` - it is dead in production and only kept alive by tests (see Loose ends). Verb dispatch is a chain of `if (verb == ...)` blocks rather than a registry.

Three pre-passes run before verb dispatch: bare bool flags `--debug`, `--quiet`, `--summary-json`, `--error-location`, `--no-auto-resolve`, `--no-auto-merge`, `--no-push`, `--continue-past-failure`, `--from-brief`, `--skip-baseline` are stripped first ([src/ThroughlineBuild.Cli/Program.cs:58-100](../../src/ThroughlineBuild.Cli/Program.cs#L58-L100)); then `--agent` / `--agent-plan` / `--agent-implement` / `--agent-review` pairs are extracted (`CliArgParser.ExtractAgentFlags`, [src/ThroughlineBuild.Cli/Program.cs:102-105](../../src/ThroughlineBuild.Cli/Program.cs#L102-L105)); for `chain` only, `--batch-implement` / `--dry-run` / `--max-depth` are then extracted ([src/ThroughlineBuild.Cli/Program.cs:110-135](../../src/ThroughlineBuild.Cli/Program.cs#L110-L135)); then ticket IDs for phase verbs are extracted ([src/ThroughlineBuild.Cli/Program.cs:172-197](../../src/ThroughlineBuild.Cli/Program.cs#L172-L197)).

Twenty action verbs plus `help` and `-V`/`--version` are reachable: `init`, `settarget`, `user-guide`, `op-doc`, `models`, `list`, `setup`, `amend`, `close`, `defer`, `reopen`, `new`, `scaffold`, `plan`, `implement`, `review`, `ship`, `chain`, `rework`, `decompose`. Any other token returns exit 2 (unknown subcommand). Five verbs dispatch before config load because they edit or ignore the config file: `init` and `settarget` (edit the config), `user-guide` (writes a doc, needs no config), `op-doc` (prints/writes an authoring spec or skeleton), and `models refresh` (rewrites the codex sizes block in place). `-V`/`--version` short-circuits when it is the sole argument ([src/ThroughlineBuild.Cli/Program.cs:27-31](../../src/ThroughlineBuild.Cli/Program.cs#L27-L31)).

### `build init [--force --print-template --no-interactive --from FILE --plane-url --workspace --project-id --project-name --token|--token-env]` - Functional
[src/ThroughlineBuild.Cli/Program.cs:231-290](../../src/ThroughlineBuild.Cli/Program.cs#L231-L290), implemented in [src/ThroughlineBuild.Cli/InitCommand.cs](../../src/ThroughlineBuild.Cli/InitCommand.cs). Bootstraps `.build/config.toml` before any config is loaded (it runs ahead of config discovery). Not an `ITicketCommand`. Unknown/misspelled flags are rejected up front with exit 2 ([src/ThroughlineBuild.Cli/Program.cs:236-250](../../src/ThroughlineBuild.Cli/Program.cs#L236-L250)) so a typo fails loudly instead of falling through to a prompt.

`init` is now connected and interactive (op-34). At a TTY with full creds and no project id/name supplied, it prompts base URL -> workspace -> token, then offers "create a new project or use an existing one": the existing path shows a most-recently-used numbered menu (pick by number, no project UUID to paste), the new path prompts for a name + identifier and resolves-or-creates via `ProjectResolver`. It then provisions states/labels (delegating to `SetupCommand`), makes a welcome commit ([src/ThroughlineBuild.Cli/WelcomeCommit.cs](../../src/ThroughlineBuild.Cli/WelcomeCommit.cs)), verifies connectivity, and prints a summary. A blank/declined token falls back to writing the offline template. `--no-interactive` suppresses all prompts.

- **Inputs:** flag values that replace `REQUIRED_*` placeholders in the template; `--token-env VAR` rewrites the literal `plane_api_token = "..."` line to `plane_api_token_env = "VAR"` and takes precedence over `--token`. `--from FILE` (or redirected stdin) reads a `key=value` credentials file via [src/ThroughlineBuild.Cli/CredsFileParser.cs](../../src/ThroughlineBuild.Cli/CredsFileParser.cs) (`plane_base_url`, `plane_workspace_slug`, `plane_api_token`, `plane_project_id`, `plane_project_name`); explicit flags win over file values. Template loaded by `ConfigTemplateLoader` from embedded resources.
- **Side effects:** with `--print-template` writes the rendered template to stdout and exits 0 before the connected probe runs (so `init --print-template` stays offline-safe). Otherwise creates `<cwd>/.build/config.toml` (UTF-8); refuses to overwrite an existing file without `--force`. On the connected path it also provisions the Plane project and makes a welcome commit.
- **Exits:** 0 success or print, 1 cancelled / Plane API error / file already exists without `--force`, 2 unknown flag.

### `build settarget [<branch> | --unset]` - Functional
[src/ThroughlineBuild.Cli/Program.cs:294-301](../../src/ThroughlineBuild.Cli/Program.cs#L294-L301), implemented in [src/ThroughlineBuild.Cli/SetTargetCommand.cs](../../src/ThroughlineBuild.Cli/SetTargetCommand.cs). Manages the `[work].target_branch` key in `.build/config.toml`. Like `init`, it runs ahead of config discovery (it edits the config). Not an `ITicketCommand`. 1. **Set** (`build settarget <branch>`) - validates the branch exists as a local git ref (`git rev-parse --verify refs/heads/<branch>`, [src/ThroughlineBuild.Cli/SetTargetCommand.cs:200-223](../../src/ThroughlineBuild.Cli/SetTargetCommand.cs#L200-L223)) then line-edits `target_branch = "<branch>"` into the `[work]` section.

- **Side effects:** rewrites `.build/config.toml` via line-edit (TOML is not parsed-and-reserialized, so comments and formatting are preserved - [src/ThroughlineBuild.Cli/SetTargetCommand.cs:234-289](../../src/ThroughlineBuild.Cli/SetTargetCommand.cs#L234-L289)).

- **Consumed by:** `ship` and the implement/chain phases via `BuildConfig.ResolveTargetBranch()` ([src/ThroughlineBuild.Cli/Config.cs:58](../../src/ThroughlineBuild.Cli/Config.cs#L58)); see [04-configuration.md](04-configuration.md) and [10-lifecycle-orchestration.md](10-lifecycle-orchestration.md).

### `build ship <ticket-id> [ticket-id ...] [--no-auto-merge]` - Functional
[src/ThroughlineBuild.Cli/Program.cs:1561-1657](../../src/ThroughlineBuild.Cli/Program.cs#L1561-L1657) (in `RunTicketVerbBodyAsync`). Deterministic phase, no worker subprocess. Resolves the merge target (`[work].target_branch` if set, else `[ship].base_branch`, [src/ThroughlineBuild.Phases/ShipPhase.cs:248-254](../../src/ThroughlineBuild.Phases/ShipPhase.cs#L248-L254)), fetches, ancestry-checks and (on clean divergence) auto-rebases the local target branch onto `<remote>/<target>`, scans for conflict markers, runs `ship.regression_checks`, fast-forward-merges the feature branch into the target, **pushes the target to the remote**, posts `[shipped_at: <sha>]`, transitions `InReview -> Done`, then decrufts the worktree. `--no-auto-merge` is threaded into `ShipOptions` ([src/ThroughlineBuild.Cli/Program.cs:1569](../../src/ThroughlineBuild.Cli/Program.cs#L1569)); `--no-push` (and `[ship].push = false`) suppress the remote push.

- **Inputs:** ticket ids; `--no-auto-merge`; `--debug` is **no longer a no-op for ship** - it makes ship stream git command output and full regression-check results to stderr (verbose mode, [src/ThroughlineBuild.Phases/ShipPhase.cs:64,82-87,442-459](../../src/ThroughlineBuild.Phases/ShipPhase.cs#L82-L87)). Ship also emits phase-level progress lines ("[ship] fetching...", "[ship] merging into <target>...") even without `--debug` ([src/ThroughlineBuild.Phases/ShipPhase.cs:80](../../src/ThroughlineBuild.Phases/ShipPhase.cs#L80)).
- **Preflight guard:** ship unconditionally checks the main worktree is on the resolved target branch (applies when targeting the base branch as well as a feature branch); if not, it emits a `wrong_worktree_branch` `GateFailure` and returns `PreFlight` failure rather than fast-forwarding the wrong ref ([src/ThroughlineBuild.Phases/ShipPhase.cs:256-277](../../src/ThroughlineBuild.Phases/ShipPhase.cs#L256-L277)). A separate pre-flight dirty-tree gate ([src/ThroughlineBuild.Phases/ShipPhase.cs:222-243](../../src/ThroughlineBuild.Phases/ShipPhase.cs#L222-L243)) refuses to ship when the feature worktree or main worktree has uncommitted tracked changes.
- **Worktree resolution:** ship matches the feature worktree by `ticket/<id>-` prefix; if none is registered it falls back to creating one from a matching local branch ([src/ThroughlineBuild.Phases/ShipPhase.cs:122-169](../../src/ThroughlineBuild.Phases/ShipPhase.cs#L122-L169)).
- **Side effects:** mutates and pushes the target branch in the main worktree (FF merge then `git push`), removes the feature worktree, optionally deletes the feature branch.
- **Exit codes:** mapped from `ShipFailureStage` at [src/ThroughlineBuild.Cli/Program.cs:1645-1655](../../src/ThroughlineBuild.Cli/Program.cs#L1645-L1655): 0 success or post-success decruft warning; 1 rebase / conflict-marker / regression / preflight gate; 4 state-check / fetch / FF-merge infra.
- **Invokes:** `ShipPhase`, `ProcessGitClient`, `BaseRefResolver` (now target-aware, [src/ThroughlineBuild.Git/BaseRefResolver.cs:13-25](../../src/ThroughlineBuild.Git/BaseRefResolver.cs#L13-L25)), `AutomatedChecksRunner`, `ConflictMarkerScanner`, `WorktreeDecrufter`, `PhaseSummaryBuilder.BuildShip`.

### `build chain <ticket-id> [ticket-id ...] [--batch-implement [<id,...>]] [--dry-run] [--max-depth <n>] [--no-auto-resolve --no-auto-merge --continue-past-failure]` - Functional
Dispatch [src/ThroughlineBuild.Cli/Program.cs:1659-1668](../../src/ThroughlineBuild.Cli/Program.cs#L1659-L1668); the body lives in the AOT-extracted helper `RunChainVerbAsync` ([src/ThroughlineBuild.Cli/Program.cs:1703-2074](../../src/ThroughlineBuild.Cli/Program.cs#L1703-L2074)). End-to-end orchestration: routes a single ticket to the appropriate starting phase by state, runs the implement-gate-review loop with `MaxReworkRounds = 2` ([src/ThroughlineBuild.Phases/ChainPhase.cs:14](../../src/ThroughlineBuild.Phases/ChainPhase.cs#L14)), then ships. A deterministic gate (`GatePhase`) now runs between implement and review: it runs the configured review checks once on the warm worktree, and its results are forwarded into `ReviewPhase` via a `PreComputedChecksRunner` so the checks are not run a second time ([src/ThroughlineBuild.Cli/Program.cs:1750-1776](../../src/ThroughlineBuild.Cli/Program.cs#L1750-L1776)). The chain phase is now constructed through the test-coverable seam [src/ThroughlineBuild.Cli/ChainPhaseComposition.cs](../../src/ThroughlineBuild.Cli/ChainPhaseComposition.cs) (`BuildChainPhase`, [src/ThroughlineBuild.Cli/Program.cs:1849-1864](../../src/ThroughlineBuild.Cli/Program.cs#L1849-L1864)). `ChainPhase` also handles parent-ticket recursion (chains non-terminal children) and an "obsolete ticket" path via an `IObsoleteRatifier`. When recursing into a parent's children, it builds a `blocked_by` dependency graph over the eligible siblings and runs them in dependency-ordered levels (lowest-ticket-number-first within a level; dependents wait for their blockers), dispatched **serially** by `SemaphoreSlim(1, 1)` - one child at a time, even within a level (op-29 removed the prior concurrent `MaxParentChainConcurrency = 4` dispatch and the `--max-parallel`/`ForceParallel` flag because parallelism was causing issues). Non-terminal stuck children (`Planning`/`InProgress`) are resumed rather than refused.

- **`--batch-implement [<id,...>]`** (op-31) batches sibling implementation in one worktree. With no list it batches ALL eligible direct children discovered at runtime (`ChainBatchImplementGroup.AllEligibleChildren`); with a comma-separated list it batches exactly that group, validated against the parent ([src/ThroughlineBuild.Cli/Program.cs:1866-1883](../../src/ThroughlineBuild.Cli/Program.cs#L1866-L1883)). Oversized groups fall back to per-ticket chaining (caps from `[batch]` config: `max_tickets`, `max_size_score`, `max_description_bytes`).
- **`--dry-run`** prints the post-order tree schedule without executing; the outcome is `DryRunPreview` (exit 0).
- **`--max-depth <n>`** caps recursion depth (default 16; non-negative integer or exit 2).
- **Multi-ticket dispatch is implemented** (the old "rejects multi-id" behavior is gone). Two paths:
  - When extra positional IDs are supplied, the verb fetches the tickets, builds a `TicketGraph` from `blocked_by` relations within the dispatched set, and runs `ParallelDispatcher` level-synchronously with concurrency bounded by `workers.max_concurrency` ([src/ThroughlineBuild.Cli/Program.cs:1886-1971](../../src/ThroughlineBuild.Cli/Program.cs#L1886-L1971)). Prints `[TKT] Outcome (Nms)` per ticket; the exit code comes from `ChainExitCodeMapper.GetExitCode(ParallelDispatchResult)`.
  - The single-ID path goes through `ChainCommand` -> `DefaultChainRunner`; a residual sequential fallback for multiple IDs via `ChainCommand` + `SequentialChainDispatcher` also exists ([src/ThroughlineBuild.Cli/Program.cs:1991-2034](../../src/ThroughlineBuild.Cli/Program.cs#L1991-L2034)). `--continue-past-failure` (otherwise descendants of a failed ancestor are skipped) is threaded into the sequential dispatcher.
- **Flags:** `--agent`/`--agent-plan`/`--agent-implement`/`--agent-review` (per-phase override; per-phase flag beats `--agent` beats config), `--no-auto-resolve` (threaded into `ChainPhaseOptions`), `--no-auto-merge`, `--no-push`, `--continue-past-failure`, `--debug`. (The `--max-parallel`/`ForceParallel` override was removed in op-29 when the parent chain became serial.)
- **Exit codes:** mapped from `ChainOutcome` by [src/ThroughlineBuild.Cli/ChainExitCodeMapper.cs:13-31](../../src/ThroughlineBuild.Cli/ChainExitCodeMapper.cs#L13-L31) (no longer an inline switch): 0 Completed / RatifiedObsolete / ParentCompleted / DryRunPreview; 2 RefusedInitialState / RefusedDirtyTree / RefusedWrongBranch / ParentHasGrandchildren; 3 StoppedAtPlan / ParentStoppedEarly / Skipped; 4 StoppedAtImplement; 5 StoppedAtReview; 6 ReworkCapExceeded; 7 StoppedAtShip; default 1. The full enum is in [src/ThroughlineBuild.Contracts/Models/ChainOutcome.cs](../../src/ThroughlineBuild.Contracts/Models/ChainOutcome.cs).
- **Invokes:** `ChainPhase` (built via `ChainPhaseComposition.BuildChainPhase` with per-phase factories incl. a `gatePhaseFactory` + `ratifierFactory` building an `ObsoleteRatifier`), `GatePhase`, `PreComputedChecksRunner`, `ParallelDispatcher`, `TicketGraph`, `ChainCommand`, `DefaultChainRunner`, `SequentialChainDispatcher`, `ChainExitCodeMapper`.
