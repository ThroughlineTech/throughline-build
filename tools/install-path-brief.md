# Brief: make `build` installable into ANY repository by a fixed, repeatable process

You are working in the Throughline Build repository. Read AGENTS.md first; it is binding.

## The goal

A person clones any repository - a Swift/iOS app, a React/Vite web app, a Python service, a
.NET solution - runs a FIXED sequence of commands, and ends with a repository that can start
`/run-backlog from Claude or $run-backlog if running from codex <ticket-id>` successfully.

The sequence must be IDENTICAL for every stack. Two handoffs to an agent are acceptable and
expected: one to derive the toolchain, one to author review invariants. Both handoffs must be
"run this command, paste the output back" - the prompts are generated by the binary and read the
repository themselves. Nothing else may require human judgment, per-repo improvisation, or
knowledge of this codebase.

Today that is not achievable. Every step reports success and the run still fails at step 0.

## What is broken today (verified 2026-08-05, binary 0.1.1+87544a0, on a fresh clone)

1. `build sop install` writes `.build/conductor.toml` with placeholder values, and
   `build sop doctor --json` then returns `passed: true, findings: []` over them. The
   placeholders are `ticket_prefix = "TICKET"`, a review invariant whose statement is the
   literal string "Replace this sentence with a true review invariant for this repository."
   with `blocks_done = true`, and `platform = "unknown"`. A freshly installed repo reports
   fully ready while carrying data that cannot drive a run.

2. `ticket_prefix` is a placeholder next to code that knows the answer. `PlaneTicketingClient`
   already resolves the Plane project identifier - it is the value that expands `620` into
   `TLB-620`. `source_roots` is hardcoded to `["src"]`, which is wrong for most repositories.

3. There is no verb for authoring review invariants. `build profile prompt` / `profile apply`
   exists for the toolchain and works well. The identical prose-to-config step for conductor
   review invariants has no surface at all, so it currently has to be done by hand-editing TOML.

4. `build sop install` emits `.agents/` and `.claude/commands/`, neither gitignored. That leaves
   an untracked working tree. The run-backlog SOP preflight requires `git status --porcelain` to
   be empty and forbids the conductor from stashing, adding, or switching branches to fix it. So
   installation manufactures the exact condition that hard-stops the workflow. The installer
   also leaves the repository on the protected branch, which the preflight rejects separately.

5. Nothing asserts run-readiness. Installation "succeeds" and the operator discovers the failure
   when the first run refuses to start.

6. `build profile derive` is the wrong shape and should be deleted. It runs the repository's
   full build and test suite plus a canary probe per gating check while printing NOTHING, so it
   reads as hung. Interrupting it leaks a git worktree and branch per attempt (four were found
   abandoned). It ignores `--agent`. It cannot run inside an agent session. Its prompt
   contradicts itself: `derive-profile-repository-prompt.md` says "Do not wrap it in a named
   block or a WORKER_RESULT envelope" and `ScaffoldProfileDeriver.BuildRepositoryBrief` then
   appends a section demanding exactly that. Nothing needs it: `profile prompt` piped to a cold
   agent and applied with `profile apply` produced a correct profile in one command.

## Reference implementation

`tools/install-build.sh` is a working prototype of the whole sequence. It has been executed end
to end against a fresh clone and it works. Treat it as an executable specification, not as code
to keep: port its behavior into the binary and DELETE it as part of this work.

Read it before designing anything. In particular note what it does after `sop install`: fixes
the ticket prefix, refuses to continue on the placeholder invariant, splices agent-supplied
invariants, cuts a run branch, commits the emitted stubs, and then asserts the SOP's own
preflight before printing READY.

## The work

Tracked as TLB-632 through TLB-636; read them with `build get`. Summary:

- **TLB-632** `sop doctor` fails closed on its own generated placeholders, with a distinct
  finding code per sentinel and an actionable message. A fresh `init` + `sop install` must make
  `sop doctor` exit non-zero.
- **TLB-633** Derive `ticket_prefix` from the resolved Plane project identifier and
  `source_roots` from the tree. Fail loudly rather than writing a placeholder.
- **TLB-634** Add `build conductor prompt` and `build conductor apply`, mirroring the profile
  pair exactly. Worker-free, stdin-capable, usable inside an agent session and in CI. The
  emitted prompt must instruct the agent to return only TOML and write no files, so a read-only
  agent sandbox suffices.
- **TLB-635** Delete `build profile derive` and its gate verifier. Fix `profile apply`: the
  refusal message names `--force-profile`, a flag the verb does not accept, and the refusal
  exits 0 so a caller cannot tell "wrote" from "refused". Canary proving moves to an explicit
  opt-in verb and out of any install path.
- **TLB-636** Add `build install`, which sequences the whole thing with progress output and
  explicit stop points, ensures the emitted stubs end up tracked and the tree clean on a
  non-protected branch, and asserts the SOP run preflight before reporting ready.

## Hard constraints

- **Stack-agnostic is the top constraint.** No language, framework, package manager, or
  directory name may be special-cased in engine code. The engine writes files and runs commands;
  stack knowledge lives in derived data. If a change would behave differently for Swift than for
  TypeScript, it is wrong.
- No install-path verb may spawn a worker agent. All of them must run inside an active agent
  session and in CI.
- AOT: source-generated `JsonSerializerContext` only, no reflection-based serialization.
  `ThroughlineBuild.Contracts` stays I/O-free.
- Every gate you add must be able to fail. Add the test that fails when the check is removed.
- `dotnet build` and full `dotnet test` green, output pasted verbatim.
- ASCII only. Commits as `TLB-NNN: short description`. Never commit to `main`.

## Definition of done

The following runs clean on a repository you did not special-case, and the last line starts a
real run:

    git clone <repo> && cd <repo>
    build install                          # deterministic; stops and prints a handoff
    <agent> "$(build profile prompt)" > profile.json
    build install --profile profile.json   # deterministic; stops and prints a handoff
    <agent> "$(build conductor prompt)" > invariants.toml
    build install --invariants invariants.toml   # deterministic; prints READY
    # open in the editor -> /run-backlog <id>

Exact flag spellings are yours to choose; the SHAPE is not negotiable: deterministic verb,
handoff, deterministic verb, handoff, deterministic verb, ready.

**Prove it on a repository that is not .NET.** A Swift/iOS app or a React/Vite app. If the
sequence only works on this repository, the work is not done. `tools/install-build.sh` and
`tools/install-path-brief.md` are both deleted when it is.
